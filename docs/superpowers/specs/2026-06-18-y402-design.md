# y402 — Design Spec

- **Date:** 2026-06-18
- **Status:** Approved design, pre-implementation
- **Owner:** Ivan Anishchuk
- **License:** CC0-1.0
- **Python:** 3.14+ (modern idiomatic; no legacy idioms)

## Summary

`y402` is a minimal, self-custodial command-line wallet whose **first job** is paying
the [x402](https://www.x402.org/) protocol on behalf of a local AI agent (initially
Claude), and which **grows into a real wallet** — broadcasting its own transactions,
holding ETH for gas, and (near-term) swapping and bridging. You `init` it once,
`topup` a couple of dollars by scanning a terminal QR, and from then on it
transparently handles `402 Payment Required` within safety caps.

The first deliverable is a CLI plus a thin Claude *skill* wrapper, usable locally
with no third party in the x402 payment path.

## Goals

- A self-custodial wallet holding a small USDC (and some ETH) balance.
- **Gasless x402 payment on the buyer side** with no middleman the buyer controls or
  pays: sign locally, hand the signed authorization to the counterparty. This is the
  default pay path and touches no RPC.
- **Be a real wallet (v1):** self-settlement — broadcast its own transactions and
  hold ETH for gas — via `web3.py`, not only sign gasless authorizations.
- **Near-term:** make it simple to **swap and bridge** (DeFi). Rails (direct on-chain
  vs. aggregator) chosen when that increment is designed.
- Safety by default: tiered confirm/refuse policy with hard caps and an audit log for
  *automated* x402 payments; an `unattended` mode for fully automated agent use.
- Multi-chain by design (EVM), starting on Base Sepolia testnet.
- Low operational friction on local desktop Linux / macOS.
- Modern, idiomatic Python 3.14+ throughout, enforced by tooling.

## Non-goals (v1)

- **Hardened headless/server key storage.** Subject to later research; v1 targets
  local desktop with the OS keyring plus a minimal encrypted-file fallback.
- **Non-EVM chains (Solana, etc.).** Different key type; future backend behind the
  same registry seam.
- **MCP server.** A later increment; the v1 agent integration is a Claude skill.
- **Multiple accounts / key rotation.**

(Swap/bridge are *near-term goals*, not non-goals — recorded now, rails decided later.)

## Background: x402 (grounded)

x402 is an HTTP-native payment protocol. The buyer-side flow:

1. Client requests a resource; the server responds `402 Payment Required` with a JSON
   body listing `accepts[]` — payment requirements, each with `scheme`, `network`
   (CAIP-2, e.g. `eip155:84532`), `asset` (token address), `payTo`, `maxAmountRequired`.
2. Client picks one it can satisfy and signs an **EIP-3009 `transferWithAuthorization`**
   (EIP-712 typed data) authorizing transfer of USDC to `payTo`. No tx is broadcast by
   the buyer on this path.
3. Client retries with the signed payload in the **`X-PAYMENT`** header — same endpoint,
   no redirects.
4. The **server** verifies and settles (directly or via *its own* facilitator) and
   returns the resource.

Consequences:

- On the gasless pay path the buyer **pays no gas** and **calls no facilitator** — the
  facilitator, if any, is the seller's infrastructure, invisible to us.
- `y402 pay` (gasless) needs **no RPC**. RPC is needed for everything else: balance,
  self-settlement/broadcast, and the future swap/bridge — and can point at the user's
  own node.
- A local library that builds a signature/tx on your machine (`x402`, `eth-account`,
  `web3.py` talking to your own RPC) is **not** a middleman.

Confirmed facts:

- Protocol networks: Base (`eip155:8453`), Base Sepolia (`eip155:84532`),
  Polygon (`eip155:137`), Arbitrum One (`eip155:42161`), World (`eip155:480`),
  Ethereum (`eip155:1`), Solana (future).
- USDC on Base Sepolia: `0x036CbD53842c5426634e7929541eC2318f3dcf7e`.
- Seller-side facilitators (referenced, not called by us): `https://x402.org/facilitator`
  (testnet), `https://api.cdp.coinbase.com/platform/v2/x402` (mainnet).
- USDC is an EIP-3009 token: `transferWithAuthorization` enables gasless transfers.

## Architecture

One Python package, layered for isolation. CLI / skill / (later) MCP are thin shims
over the core.

### `wallet` — eth-account-led, the trust root

Owns the key and all signing; the private key lives here and is **never** handed to the
`x402` package.

- Key lifecycle: generate, load, address.
- Signing: `sign_typed_data` (EIP-712 — used for EIP-3009 / x402), `sign_message`,
  `sign_transaction` (for self-settlement / broadcast).
- Deliberately general so swap/bridge and other ops layer on later.

### `keystore` — key-at-rest

- Primary: OS keyring (`keyring`: Secret Service / libsecret, macOS Keychain).
- Fallback (auto when no keyring): minimal encrypted JSON keystore (eth-account
  `encrypt`/`decrypt`), passphrase from `Y402_PASSPHRASE` env or prompt.
- Never a plaintext key. Hardened headless storage is parked research.

### `chain` — on-chain interaction (web3.py)

The capability that makes y402 a real wallet. Per-network `Web3` client built from the
registry's `rpc_url`:

- Reads: ERC-20 (USDC) balance + native ETH balance.
- Writes: gas estimation, nonce management, broadcast a `wallet`-signed transaction
  (`eth_sendRawTransaction`), await receipt.
- Foundation for self-settlement now and swap/bridge later.

### `registry` — network definitions (the multi-chain seam)

Mapping `eip155:<id>` → `{ chain_id, rpc_url, usdc_address, eip712_domain, enabled }`.
Adding a chain = adding an entry. v1 ships **Base Sepolia enabled**, Base mainnet and
other EVM networks present but disabled / addable. EVM-only in v1 (one secp256k1 key =
same address on every EVM chain).

### `x402` integration — protocol formatter we drive

Official `x402` package parses `402` `accepts[]` and produces the EIP-712 typed-data;
**`wallet` signs it**; we assemble `X-PAYMENT` and retry. The package never holds the
key; no client-side facilitator is configured. Default path is gasless (no RPC).

### `policy` + audit

Governs *automated* x402 payments (the agent-facing path):

- **Tiered (default):** auto-pay ≤ `auto_threshold` (`$0.01`); **confirm** up to
  `per_payment_cap` (`$0.10`); **refuse** above. Cumulative `daily_cap` (`$1.00`),
  rolls over daily.
- **`unattended`:** confirm band flips to auto-approve; caps still hard-refuse above.
  The mode the skill (and later MCP) pass through.
- Every decision (amount, host, network, resource) appended to a JSONL **audit log**.

Explicit user-initiated transfers (`send`, self-settlement) are *not* automated: they
confirm interactively by default (`--yes` to skip), and are audit-logged too.

### Shims

- **`cli`** (`typer` + `rich`): `init`, `topup`, `balance`, `pay`, `send`, `config`, `log`.
- **`skill`**: a thin Claude `SKILL.md` that shells to `y402 pay --unattended`.
- **`mcp`** (later): thin FastMCP server.

## Data flow

**`y402 pay <URL>` (gasless, default):** request → `402` → parse `accepts[]`, keep
registry-enabled networks, select (prefer default network, else lowest amount) →
`policy` check → `x402` typed-data → `wallet` signs → `X-PAYMENT` retry → body →
audit log. **No RPC touched.**

**`y402 send <to> <amount>` / self-settlement:** build tx → `chain` estimates gas +
nonce → `wallet` signs → confirm (unless `--yes`) → `chain` broadcasts → await receipt
→ audit log. **Needs RPC + ETH for gas.**

## Payment policy & safety — defaults

| Setting | Default | Meaning |
| --- | --- | --- |
| `auto_threshold` | `$0.01` | Pay silently at/under this (automated x402). |
| `per_payment_cap` | `$0.10` | Confirm up to here; refuse above (automated x402). |
| `daily_cap` | `$1.00` | Cumulative per-day refuse ceiling (automated x402). |
| `unattended` | `false` | Flip the confirm band to auto-approve. |

CLI overrides: `--unattended`, `--max <usd>`, `--network <id>`, `--yes`.

## CLI commands

- `y402 init` — generate key, store via keystore, print address.
- `y402 topup` — print address + a **terminal QR** (`qrcode`); receive USDC and/or ETH
  (ETH funds gas for self-settlement) on a chosen network.
- `y402 balance [--network <id>]` — USDC + ETH per enabled network (uses RPC).
- `y402 pay <URL>` (alias `fetch`) — gasless x402, auto-handled per policy; returns body.
- `y402 send <to> <amount> [--asset usdc|eth] [--network <id>]` — broadcast a transfer
  (self-settlement); confirms unless `--yes`; needs ETH for gas.
- `y402 config [get|set] …` — caps, `unattended`, default network, RPC URLs.
- `y402 log` — tail the audit log.

## Claude skill integration (v1 agent face)

A `SKILL.md` instructing the agent to call `y402 pay --unattended <URL>` on a paywalled
/ `402` endpoint and surface the body. No logic in the skill — custody, policy, chain,
and protocol all live in the CLI/core.

## Configuration & file layout

- Config directory: `~/.config/y402/` (XDG).
  - `config.toml` — caps, default network, RPC URLs, keystore backend hint.
  - `audit.jsonl` — append-only log of payments and transfers.
  - encrypted keystore file (only when the keyring fallback is in use).
- Read config with stdlib `tomllib`; write with `tomli-w` (no `tomlkit`).
- Key material in the OS keyring on the happy path; otherwise the encrypted file.

## Scaffolding & tooling

Scaffold from the **`cli`** cookiecutter in `~/src/python-project-templates`:

```bash
uvx cookiecutter ~/src/python-project-templates --directory cli
# project_name=y402, package_name=y402, license=CC0-1.0,
# python_version=3.14, use_mypy/use_ty/use_basedpyright=true
```

The already-committed `docs/` (this spec) is layered into the generated tree; y402
modules are added under `src/y402/`. The template provides: `pyproject.toml` (uv, ruff,
type-checkers, pytest+coverage, hatchling), `src/` layout with `py.typed`,
`.pre-commit-config.yaml`, full GitHub Actions CI/CD, `SECURITY.md`, `CHANGELOG.md`
(Keep a Changelog), `CLAUDE.md`, Dependabot, branch-protection-as-code.

- **Package manager:** uv. **Lint/format:** ruff (incl. `UP` pyupgrade, `PTH` pathlib,
  `S` bandit, `TRY`, `SIM`). **Types:** ty + mypy(strict) + basedpyright. **Tests:**
  pytest + coverage.
- **Modern idiom, enforced:** `requires-python = ">=3.14"`, ruff `target-version =
  "py314"`. Use `X | None`, builtin generics, `match`, `pathlib`, `StrEnum`,
  `@dataclass(slots=True)`, `type` aliases. No `Optional`/`Union`/`typing.List`,
  no `os.path`. `UP`/`PTH` + strict type-checkers reject the legacy forms.
- The `CLAUDE.md` (the original `/init` deliverable) is produced as part of scaffolding
  and filled with the real build/test commands and the module map above.

## Dependencies

- `x402` — protocol layer (typed-data / payload construction). Local code, no facilitator.
- `eth-account` — wallet, key management, EIP-712 / EIP-3009 signing (trust root).
- `web3` — chain interaction: balance reads, gas/nonce, broadcasting (self-settlement).
- `keyring` — OS keyring with fallback.
- `qrcode` — terminal QR for `topup`.
- `httpx` — HTTP client for the x402 exchange.
- `typer` + `rich` — CLI (template defaults).
- `tomli-w` — config writing (reads via stdlib `tomllib`).
- (later) `mcp` — MCP server wrapper.

## Testing strategy (TDD)

- **Unit:** policy engine (thresholds, caps, daily rollover); network selection from
  sample `accepts[]`; config round-trip; keystore backend selection (mocked keyring +
  forced-fallback); EIP-3009 typed-data assembly + signature verification with a known
  key; `chain` gas/nonce/encode logic against a mocked provider.
- **Integration:** Base Sepolia faucet USDC/ETH against a local EVM (anvil/eth-tester)
  or testnet — exercise the gasless `pay` path and the self-settle `send`/broadcast
  path end-to-end, plus one real testnet x402 smoke test.

## v1 scope vs later

- **v1:** `wallet`, `keystore`, `chain` (web3.py), `registry`, gasless x402 `pay`,
  self-settlement `send`/broadcast (+ ETH gas), `policy` + caps + audit, the CLI
  commands, the Claude skill, Base Sepolia (registry ready for mainnet), single EVM key.
- **Near-term:** swap & bridge (DeFi; rails TBD).
- **Later:** MCP wrapper, Solana / non-EVM backend, headless key hardening, multi-account.

## Open decisions (deferred deliberately)

- **DeFi rails** for swap/bridge: direct on-chain (DEX router / bridge contracts) vs.
  aggregator API (a third-party service, in tension with the no-middleman ethos).
  Decided when that increment is designed.
